# Ascend 910B2 tiny validation, 2026-10-04

The tests ran in the Kunlun `shensi-npu-tiny` VSCode environment, with one Ascend 910B2 (64 GB), CANN 9.1.0-beta.1, Python 3.11.15, PyTorch 2.10.0+cpu, and torch_npu 2.10.0. The project was copied into a **new** `/root/work/shensi-ascend` directory. The platform's existing `/root/work/shensi-offline` and `/root/work/filestorage` were only read, never edited. No Jupyter notebook was used.

The independent NPU reference preflight passed (`preflight.json`); it allocated an NPU tensor, ran matrix multiplication and backward, and found one device. Single-rank HCCL passed (`hccl.log`). All 16 incremental regression tests passed, with zero failures/errors/skips (`pytest.xml`). The FP32/full, BF16/full and FP32/per-head tiny synthetic-data runs all reported `ok: true`. Each executed pretrain, midtrain, SFT, a single-process RL math reference, a single-process OPD math reference, optimizer/checkpoint restore, HF export/reload, and generation on `npu:0`. All three restore parameter deltas and export/reload logit deltas were 0. The first and last supervised losses were 4.131523 → 3.743316 (FP32/full), 4.131402 → 3.748037 (BF16/full), and 4.131524 → 3.743295 (FP32/per-head). These losses establish a functioning tiny computation chain, not model quality.

The first pytest attempt found an **environment** problem: a preinstalled, broken torchvision advertised itself to Transformers but lacked the `torchvision::nms` operator. In the new project directory only, `.npu_env/sitecustomize.py` hid torchvision from Python package discovery for this text-only test. The second complete run passed. `checks_retry.log` records the full run. The evidence archive `reference-evidence.tgz` was transferred from the remote VSCode editor as base64 and SHA256 verified (`86ff3f0d5cee9433be29eafae7522cdb05787574aca37bd987182ee1334c2d1a`); the extracted original reports and logs are in `artifacts/`.

This reference run does **not** validate Megatron's native training loop, verl actors/rollouts, vLLM-Ascend serving, OpenCompass, multi-card training, or CUDA regression. Those require separate native dependencies and checks. See `ASCEND_ADAPTATION.md` for the current native-stack attempt and remaining limits.
